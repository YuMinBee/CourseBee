CourseBee Labs 개발팀 업무 절차

작업 시작
개발 작업은 이슈 번호와 완료 조건을 먼저 확인한 뒤 시작한다. 요구사항이 불명확하면 구현 전에 제품 담당자와 범위를 합의한다. 하나의 변경에는 하나의 명확한 목적을 두고 관련 없는 수정은 별도 작업으로 분리한다.

코드 변경과 검토
기능 브랜치에서 작업하고 변경 이유, 테스트 방법, 영향 범위를 Pull Request에 기록한다. 작성자는 자동 테스트 결과를 확인한 뒤 검토를 요청한다. 검토자는 동작 오류, 보안 위험, 테스트 누락, 운영 영향을 중심으로 확인한다.

배포
메인 브랜치에 병합된 변경은 CI 검증을 통과해야 배포 후보가 된다. 배포 전에는 데이터 변경과 되돌리기 방법을 확인한다. 배포 후에는 핵심 상태 확인과 오류 로그를 점검하고 문제가 발생하면 정해진 롤백 절차를 따른다.

장애 대응
서비스 장애를 발견한 구성원은 장애 채널에 증상, 발생 시각, 영향 범위를 공유한다. 담당자는 복구를 우선하고 확인되지 않은 원인을 단정하지 않는다. 복구 후에는 원인, 대응 과정, 재발 방지 작업을 회고 문서에 기록한다.
