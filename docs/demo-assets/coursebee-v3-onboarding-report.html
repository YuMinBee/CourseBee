Executive briefing

핵심 브리핑

개발 작업은 이슈 번호와 완료 조건을 먼저 확인한 뒤 시작한다. 요구사항이 불명확하면 구현 전에 제품 담당자와 범위를 합의한다. 하나의 변경에는 하나의 명확한 목적을 두고 관련 없는 수정은 별도 작업으로 분리한다.

모든 업무 계정은 다중 요소 인증을 활성화해야 한다. 비밀번호는 개인 서비스와 재사용하지 않으며 동료와 공유하지 않는다. 권한은 업무에 필요한 최소 범위로 요청하고 역할이 변경되면 불필요한 권한을 반납한다.

CourseBee Labs 개발팀 업무 절차

  • 개발 작업은 이슈 번호와 완료 조건을 먼저 확인한 뒤 시작한다. 요구사항이 불명확하면 구현 전에 제품 담당자와 범위를 합의한다. 하나의 변경에는 하나의 명확한 목적을 두고 관련 없는 수정은 별도 작업으로 분리한다.[1]
  • 기능 브랜치에서 작업하고 변경 이유, 테스트 방법, 영향 범위를 Pull Request에 기록한다. 작성자는 자동 테스트 결과를 확인한 뒤 검토를 요청한다. 검토자는 동작 오류, 보안 위험, 테스트 누락, 운영 영향을 중심으로 확인한다.[1]
  • 메인 브랜치에 병합된 변경은 CI 검증을 통과해야 배포 후보가 된다. 배포 전에는 데이터 변경과 되돌리기 방법을 확인한다. 배포 후에는 핵심 상태 확인과 오류 로그를 점검하고 문제가 발생하면 정해진 롤백 절차를 따른다.[2]
  • 서비스 장애를 발견한 구성원은 장애 채널에 증상, 발생 시각, 영향 범위를 공유한다. 담당자는 복구를 우선하고 확인되지 않은 원인을 단정하지 않는다. 복구 후에는 원인, 대응 과정, 재발 방지 작업을 회고 문서에 기록한다.[2]

CourseBee Labs 정보보안 온보딩 정책

  • 모든 업무 계정은 다중 요소 인증을 활성화해야 한다. 비밀번호는 개인 서비스와 재사용하지 않으며 동료와 공유하지 않는다. 권한은 업무에 필요한 최소 범위로 요청하고 역할이 변경되면 불필요한 권한을 반납한다.[3]
  • 업무 자료는 승인된 기기와 회사가 지정한 저장소에서만 처리한다. 고객 정보와 내부 문서를 개인 이메일, 개인 클라우드, 공개 메신저로 전송하지 않는다. 화면을 비울 때는 기기를 잠그고 운영체제와 보안 업데이트를 미루지 않는다.[3]
  • 출처가 불분명한 링크와 첨부파일은 열지 않는다. 의심스러운 로그인 알림, 계정 탈취 가능성, 자료 오발송을 발견하면 삭제하거나 숨기기 전에 보안 담당 채널로 즉시 신고한다. 신고 내용에는 발생 시각, 사용한 기기, 확인한 현상을 포함한다.[4]
  • 내부 문서를 외부와 공유하려면 문서 소유자와 보안 등급을 확인한다. 공개 가능한 자료인지 불분명하면 공유하지 않고 담당자의 승인을 요청한다. 외부 공유 링크에는 필요한 기간과 대상만 접근할 수 있도록 만료일과 권한을 설정한다.[4]
