# 운영 배포 및 롤백 가이드

- 소관: SRE팀 (팀장 김도윤)
- 대상: 데이터허브(DataHub) 운영 환경 (Kubernetes, Argo CD)
- 최종 개정: 2026년 7월 6일 (카나리 단계별 관찰 시간 10분 → 15분 변경)

## 1. 배포 일정
- 정기 배포는 매주 화요일과 목요일 오후 2시부터 5시 사이에 진행한다.
- 금요일, 공휴일 전날, 배포 동결 기간에는 배포하지 않는다.
- 위 기간에 꼭 필요한 긴급 핫픽스(P1·P2 장애 조치)는 CTO 승인을 받은 경우에만 배포할 수 있다.
- 정기 배포 동결 기간: 설·추석 연휴 시작 2영업일 전부터 연휴 다음 영업일까지, 연말(12월 24일~1월 2일). 구체적인 일정은 엔지니어링 주간 회의에서 공지한다.

## 2. 배포 사전 준비
1. Jira DEPLOY 프로젝트에 배포 요청 티켓을 생성하고 포함된 PR, 변경 내용, 롤백 방법을 적는다.
2. 팀장 승인을 받는다.
3. QA팀이 스테이징 환경 검증을 마치고 티켓에 QA sign-off를 남긴다.
4. DB 스키마 변경이 있으면 배포 전 영업일까지 DBA 리뷰를 완료한다. 스키마 변경은 이전 버전 애플리케이션과 호환(backward compatible)되어야 한다.
5. 배포 30분 전에 Slack #deploy 채널에 배포 예정 공지를 올린다.

## 3. 카나리 배포 단계

| 단계 | 트래픽 비율 | 최소 관찰 시간 | 진행 조건 |
|---|---|---|---|
| 1단계 | 5% | 15분 | 에러율·지연시간 정상 |
| 2단계 | 25% | 15분 | 에러율·지연시간 정상 |
| 3단계 | 100% | 30분 | 배포 완료 선언 |

- 각 단계는 Argo Rollouts가 자동으로 진행하며, 배포 담당자는 Grafana 'Deploy Overview' 대시보드를 지켜본다.
- 2026년 6월 12일 장애 이후 1·2단계 관찰 시간을 10분에서 15분으로 늘렸다.

## 4. 자동 롤백 기준
카나리 단계 또는 배포 완료 후 30분 이내에 다음 조건 중 하나라도 충족되면 Argo Rollouts가 자동으로 이전 버전으로 롤백한다.

- HTTP 5xx 에러율이 2% 이상인 상태가 5분 동안 지속
- API p95 응답시간이 배포 직전 1시간 평균보다 50% 이상 높은 상태가 5분 동안 지속
- 신규 파드(Pod)의 재시작이 10분 안에 3회 이상 발생

## 5. 수동 롤백 절차
자동 롤백 기준에 해당하지 않더라도 기능 오류가 확인되면 배포 담당자가 즉시 수동으로 롤백한다.

1. Argo CD 콘솔에서 해당 애플리케이션을 선택한다.
2. [History and Rollback] 탭에서 직전 정상 revision을 선택하고 [Rollback]을 실행한다.
3. 롤백 완료 후 Grafana에서 에러율과 응답시간이 정상으로 돌아왔는지 확인한다.
4. Slack #deploy 채널에 롤백 사실과 사유를 공지한다.
5. 고객 영향이 있었다면 「서비스 장애 대응 Runbook」에 따라 장애로 등록한다.

- DB 마이그레이션이 포함된 배포는 애플리케이션만 롤백하고, 스키마 롤백은 DBA와 협의 후 별도로 진행한다.

## 6. 배포 후 확인
배포 완료 후 30분 동안 배포 담당자는 자리를 비우지 않는다. 이상이 없으면 DEPLOY 티켓을 'Done'으로 변경하고 릴리스 노트를 Confluence에 게시한다.
