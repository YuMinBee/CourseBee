# 계정 및 접근권한 관리 지침

- 문서번호: SEC-GUD-003
- 시행일: 2025년 6월 1일 (2026년 4월 1일 MFA 관련 조항 개정)
- 소관: 정보보호팀 / 운영: IT지원팀

## 1. 계정 체계
- 모든 임직원은 하나의 SSO 계정(Okta)으로 메일, Slack, 한빛워크, Jira, Confluence, GitHub Enterprise에 로그인한다.
- 계정 ID는 '이름.성' 형식의 영문 소문자로 만든다. (예: 김하늘 → haneul.kim) 동명이인은 끝에 숫자를 붙인다.
- 계정은 개인에게만 부여하며, 여러 사람이 함께 쓰는 공용 계정은 만들 수 없다. 시스템 간 연동에 필요한 서비스 계정은 SRE팀이 별도로 관리한다.

## 2. 신규 입사자 계정 발급
1. 인사팀은 입사일 5영업일 전까지 입사 예정자 정보를 IT지원팀에 전달한다.
2. IT지원팀은 입사일 1영업일 전까지 SSO 계정을 생성하고 기본 권한 그룹을 부여한다.
3. 입사 첫날 IT지원팀이 임시 비밀번호를 대면으로 전달한다. 임시 비밀번호는 24시간 동안 유효하며 첫 로그인 시 반드시 변경해야 한다.
4. 첫 로그인 직후 Okta Verify 앱으로 MFA 기기를 등록한다.

## 3. 접근권한 신청
- 기본 권한 그룹(메일, Slack, 한빛워크, 사내 위키) 외의 권한은 한빛워크 [권한 신청] 메뉴로 요청한다.
- 일반 시스템 권한은 해당 시스템 오너의 승인을 받는다.
- 운영(Production) 환경 접근 권한은 팀장과 SRE팀장의 승인을 모두 받아야 하며, 유효기간은 6개월이다.
- 개인정보가 포함된 시스템의 권한 기준은 「개인정보 처리 지침」을 따른다.
- 정보보호팀은 분기마다 전체 권한을 재검토하고, 불필요한 권한을 회수한다.

## 4. 장기 미사용 계정
90일 동안 한 번도 로그인하지 않은 계정은 자동으로 잠긴다. 잠금 해제는 팀장 승인 후 IT 헬프데스크 포털로 요청한다.

## 5. 휴직 및 부서 이동
- 30일 이상 휴직하는 경우 휴직 시작일에 계정을 일시 정지하고, 복직일에 다시 활성화한다.
- 부서를 이동하면 이전 부서의 권한은 이동일에 회수되며, 새 부서의 권한은 다시 신청한다.

## 6. 퇴사자 계정 처리
1. 퇴사일 오후 6시에 SSO 계정이 비활성화되어 모든 시스템 접속이 차단된다.
2. 퇴사자의 메일함은 퇴사일로부터 30일간 보존한 뒤 삭제한다. 업무 인수인계에 필요한 메일은 팀장이 보존 기간 내에 IT지원팀에 이관을 요청한다.
3. 퇴사자가 소유한 Google Drive·Confluence 문서는 팀장에게 소유권이 이전된다.
4. GitHub Enterprise의 개인 저장소는 퇴사일에 보관 처리(archive)된다.

## 7. 계정 보안 수칙
- 비밀번호 기준과 MFA 적용 기준은 「정보보안 정책」 최신 버전을 따른다.
- 타인의 계정을 빌려 쓰거나 본인 계정을 빌려주는 행위는 금지한다.
- 본인이 하지 않은 로그인 알림을 받으면 즉시 보안사고로 신고한다.
